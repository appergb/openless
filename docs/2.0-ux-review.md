# Core 2.0 体验梳理与页面改进

状态：draft；阶段：implementation-backed；更新：2026-09-07。

## 基线与结论

实时抓取 `Open-Less/openless` 后确认，#1019 将 Core 2.0 合并到默认主线 `beta`，提交 `fc38edd1a3da3a4f2fa56f433be84278c3456ed1`。稳定 `main` 是 1.3.18 的 `08d70601`。本次按用户授权删除应用仓库旧的未提交修改，用前者替换工作区，再建立 `feat/core-2-ux-linux`。

项目名为 OpenLess，迁移名为 **Core 2.0**；应用显示版本 `2.0.0-Beta.1` 与后端公开合同 `2.0.0` 是不同概念。范围仍以 [2.0 需求](2.0-requirements.md)为准。

2.0 的重要收益是业务状态、渠道、迁移与会话取消进入共享 Core。主要体验问题是新架构已就位，界面仍让用户自己推断操作顺序：主页以统计为主，设置混放大量任务，Linux 原有领域界面顺序堆叠。本次优先整理现有功能的入口与显示，不增加另一套业务规则。

## 迁移领域与页面影响

本次按 #1019 的变更清单、公开合同、领域出口、平台交接与实际页面梳理；下表是迁移面索引和体验判断，不是逐行安全审计或全部设备验收。

| 领域 / 桌面验收项 | 2.0 相关实现 | 体验判断与本次处理 |
| --- | --- | --- |
| 启动、生命周期 D01 | `App.tsx`、IPC `shared.ts`、Core `api.rs` | 保留所有窗口的合同检查；补可读启动状态、重查按钮与折叠错误详情 |

## 已落实的界面设计

- **主页**：下一步与状态刷新前置；未读取/读取失败/未配置分别处理；本地 ASR、云 ASR 和 Omni 依据已有真实状态呈现；服务卡有配置/管理入口。活动热力图置于近期结果之后，底部卡片自然延展而不被短窗口压扁。
- **设置**：录音与输入、快捷键与选区、AI 服务与模型、外观与语言、权限与数据、实验与扩展、关于与更新。稳定的旧 section ID 保留；分类搜索支持当前语言的用途和关键词，不搜索或暴露凭据值。
- **AI 分区**：语言模型、语音识别、本地模型、连接与扩展各自呈现，页签随滚动保留；Omni 模式使用对应入口，避免传统模型页变空白。设置实底，不透出背后的页面文字。
- **操作细节**：搜索不卸载当前分类草稿；选分类回到页首；Escape 先清空查询、再关闭；打开时移动焦点、关闭时返回入口；已有下拉和快捷键录制优先处理自己的按键。
- **页面排布**：设置关键解释直接可读；共享页头不再被内容压缩，操作按钮可换行；历史窗口小于1000像素时用列表/详情切换，缩窗保留正在查看的重润色结果；翻译和划词追问补上已有用途说明。
- **入口修复**：空本地模型目录在布局阶段反复写入相同选择值，浏览器可复现最大更新深度错误。增加变化判断后，同一服务入口恢复正常。下拉选项补可访问关联，快捷键小菜单优先消费 Escape。
- **渠道与表单**：列表改用统一分隔行，显示名称、模型、当前使用/停用、验证结果与时间；添加放在分区头部，验证/启停/编辑操作有标签。表单按服务连接、模型设置、连接验证组织，名称作为可选信息，删除仍需确认；顶部关闭、Tab循环、子菜单Escape与焦点返回已补齐。
- **模型与下载**：管理页减少嵌套卡片，已下载/下载中模型与所选详情各有清楚位置；空态提供下载与重新读取。下载目录有模型大小、引擎、状态、仓库和简介；仅多引擎时显示筛选，窄屏按目录/详情切换，底部操作独立滚动。保留Windows原引擎操作与取消/激活合同。
- **Linux**：实际界面行为统一记录在 [04 页面与领域操作](linux-egui-handoff/04-ui-domains.md)，剩余事项统一记录在 [02 缺口登记](linux-egui-handoff/02-gap-register.md)。

## 下一轮建议与优先级

| 优先级 | 建议 | 依据与验收 |
| --- | --- | --- |
| P1 | 将单项配置检查连接成首次听写向导 | 渠道列表现已区分当前使用与上次验证；下一步串联麦克风、服务和目标输入检查，让新用户完成一条真实听写 |
| P1 | 优先跑首装与升级后的第一条听写闭环 | 2.0 改动大量 Host/Core 边界。分别验证权限拒绝、设备断开、快捷键冲突、取消与最终落字，保留清楚的恢复入口 |
| P1 | Linux 先完成输入环境和后台工作可达，再补领域功能 | L01–L03 涉及热键、上下文、录音，直接影响后续历史/纠错。真机覆盖 X11/Wayland 和常用目标应用；不以页面数替代功能闭环 |
| P2 | 将主快捷键的编辑统一到一个明确目的地 | 当前录音页和快捷键页都有入口，属于既有行为；下一轮可保留录音页摘要并跳到快捷键编辑，需同步首次引导与迁移提示 |
| P2 | 本地/云选择围绕用户需求表达 | 用离线、速度、语言和设备需求组织模型选择；模型实际可用、下载中、加载中、失败分别反馈，不默认“已下载”等于可识别 |
| P2 | Linux 跟进模型、历史、词汇/风格/市场完整操作 | 具体范围已在 L04–L09；已有 Core API 可复用，优先交付有完整成功/失败/取消路径的一个领域 |
| P2 | 页面能力来自 Host，并给不支持项明确原因 | Linux 能力快照中的 overlay/AppImage flag 不代表 UI/更新器已接好；后续能力合同可携带不可用原因，避免两端界面各自猜测 |
| P3 | 按领域拆解持续增长的门面和原生 UI 文件 | `Core api.rs` 与 Linux `main.rs` 较大，增加定位和回归成本；在领域功能实际扩展时拆分，避免无业务目的的全面重写 |

## 浏览器预览目录

普通浏览器此前的 `listProviderDescriptors` 返回空数组，2.0 渠道编辑只能停留在加载态。现在浏览器分支懒加载 Core 生成的公开目录；原生分支仍执行同一个受启动合同保护的 IPC。该文件只有公开服务元数据，没有用户凭据或认证状态，Core 继续是规则的唯一来源。

生成文件：`openless-all/app/src/lib/ipc/provider-descriptors.generated.json`（generated，不手工维护）。在应用目录执行以下命令重新生成：

```sh
cargo run --locked -p openless-core --example export_provider_descriptors
```

生成器只调用 `openless_core::provider_rules::provider_descriptors`，没有启动应用、打开密钥环或请求外部服务。对应浏览器入口测试覆盖 ASR、LLM、Omni 目录可加载及协议字段完整性。
